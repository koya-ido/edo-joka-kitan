# 開発知見・テンプレート改善 TODOバッファ

本書は、Webアプリケーション開発サイクル（特に垂直スライス実装中）において生じたコーディング規約、エージェントスキル、設計ドキュメントの齟齬・改善点をリアルタイムに蓄積するためのバッファファイルです。
蓄積された知見のうち、汎用的なものは `reflect-template-updates` スキルを通じてマスターテンプレート（`.agents/`）へ対話型で還元します。

## 1. 運用の手引き

- **記録のタイミング**:
  - 実装中に「このチェック観点がスキルに抜けていた」「規約と実際の挙動にズレがあった」「プロンプトをこう変えたらエージェントの精度が上がった」と気づいた瞬間に追記します（人間・AIエージェントの双方が追記可能）。
- **汎用性分類の基準**:
  - `[全PJ共通]`: 技術スタックに関係なく、全Webアプリ開発初期セットに適用すべき汎用知見（マスターのスキル・READMEへ還元）。
  - `[技術依存]`: 特定の言語・FW・ORM（例: Next.js, Prisma, FastAPI等）に依存する知見（将来のスタック別プリセットや特化レビュースキルへ還元）。
  - `[当該PJ固有]`: 当該プロジェクト独自のドメインロジック・業務ルールに閉じた知見（マスターへは還元せず本PJ内で完結）。
- **マスター還元の実行**:
  - プロジェクト完了時（Phase 5）またはスライス一段落時に `/reflect-template-updates` スキルを呼び出します。

## 2. 記録フォーマット（標準雛形）

新しい改善候補を記録する際は、以下のブロックをコピーして [3. 改善候補リスト（未反映）](#3-改善候補リスト未反映) の末尾に追記してください。

```markdown
### [ITEM-XXX] <簡潔な改善タイトル>

- **対象**: <初期スキル名 / README.template.md / 共通規約など>
- **汎用性分類**: <全PJ共通 / 技術依存 / 当該PJ固有>
- **ステータス**: 未反映
- **事象・課題**:
  - <何が起きたか、どのような不都合・二度手間が発生したか>
- **改善案**:
  - <どのように修正・追記すべきか。具体的な修正diffや追加テキスト案>
```
