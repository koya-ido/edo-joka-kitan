# プロジェクト企画提案書 (RFP)

本書は、新規Webアプリケーション開発における企画構想、解決したい課題、主要機能、および制約条件を整理するための企画提案書（RFP: Request for Proposal）のテンプレートです。
各項目に記載された記入例（`（例: ...）`）を参考に、手書きでラフに箇条書きするか、または `rfp-interview` スキルを活用して対話形式で具体化してください。

## 1. プロジェクト概要

- **プロダクト名（仮）**:
  - _（例: TeamSync - 開発チーム向け軽量日報・ブロッカー可視化ツール）_
- **一言説明（エレベーターピッチ）**:
  - _（例: 忙しいエンジニアが1分で本日の成果とブロッカーを記録し、チーム内のタスク停滞を即座に検知・解消できるWebアプリ）_
- **目標・目指す成果（成功基準）**:
  - _（例: チーム全員（10〜20名）が毎夕無理なく継続投稿でき、翌朝のスタンドアップ前に誰が何で詰まっているかが一目で把握できる状態を作る）_

## 2. 背景と解決したい課題

- **現状の課題・ペインポイント**:
  - _（例: 既存のチャットツール（Slack等）では日報がタイムラインで流れてしまい、未解決のブロッカーが埋もれやすい）_
  - _（例: スプレッドシートでの管理は入力負荷が高く、更新が形骸化している）_
- **なぜ今このプロダクトを作るのか（開発動機）**:
  - _（例: フルリモート体制への移行に伴い、非同期での状況把握と課題の早期発見が急務となったため）_

## 3. 想定ユーザーと利用シーン

- **メインターゲット（ペルソナ）**:
  - _（例: ソフトウェア開発チームのエンジニアメンバーおよびプロジェクトマネージャー（10〜30名規模））_
- **主な利用シーン・導線**:
  - _（例: メンバーは退勤前の1分間でPCブラウザからサクッと入力・投稿する）_
  - _（例: PMは毎朝の始業時にダッシュボードを開き、「要対応」フラグが立った日報を確認してフォローする）_

## 4. コア機能要件

> [!TIP]
> 「○○または○○」といった曖昧な記述は避け、Must（初期リリース必須）と Nice-to-have（将来検討）を明確に分けてください。

- **Must（初期リリース必須機能）**:
  - _（例: 日報の作成・編集・削除機能（マークダウン入力、本日の成果/明日の予定/ブロッカーのテンプレート自動挿入））_
  - _（例: 日報一覧表示・日付/ユーザー別フィルタリング・キーワード検索機能）_
  - _（例: ブロッカーフラグ機能（投稿時に「困りごとあり」にチェックを入れると一覧でバッジ強調表示））_
  - _（例: ユーザー認証機能（ログイン・ログアウト・セッション管理））_
- **Nice-to-have（将来検討・優先度低）**:
  - _（例: Slack Webhookへの投稿自動通知連携）_
  - _（例: LLMによる日報要約および週次振り返りレポート生成機能）_
  - _（例: 投稿に対するスタンプリアクションやコメント機能）_
- **扱う主要データ・エンティティのイメージ（保存・管理したい対象）**:
  - _（例: ユーザー（氏名、ロール）、日報（日付、成果、予定、ブロッカー有無、作成者）、コメント）_

## 5. 非機能要件・運用制約

- **想定ユーザー規模・アクセス頻度**:
  - _（例: 初期登録ユーザー30名程度、ピーク時は夕方（18:00〜19:00）に同時10名程度がアクセス）_
- **セキュリティ・認可要件（認証方式、管理者権限、個人情報有無等）**:
  - _（例: 一般メンバーは自身の日報のみ編集・削除可能、管理者は全メンバーの日報閲覧・削除およびメンバー招待が可能）_
  - _（例: 社外への一般公開は行わず、許可された社内ドメインのユーザーのみアクセス可能とする）_
- **対応デバイス / ブラウザ環境**:
  - _（例: PCブラウザ（Google Chrome, Safari最新版）を主対象とする。スマートフォンは閲覧のみ崩れず表示できれば可）_
- **インフラ・コスト制約（無料枠重視、特定クラウド指定等）**:
  - _（例: 初期はランニングコストを抑えるため、Vercel / Supabase 等の無料枠〜低コストプランの範囲内で運用したい）_

## 6. 対象外事項 (Out of Scope)

> [!IMPORTANT]
> スコープの肥大化（スコープクリープ）を防ぐため、初期フェーズでは「あえて作らないこと」を明記します。

- **今回は実装しない機能・ユースケース**:
  - _（例: モバイルネイティブアプリ（iOS / Android）の作成（Webブラウザ利用に限定））_
  - _（例: リアルタイムチャット機能（Slack等の外部ツールで代替するためアプリ内には作らない））_
  - _（例: 複雑な組織階層（複数部署・チームのネスト構造）の管理）_
  - _（例: 課金・決済（Billing）処理や外部SaaSへのデータエクスポート機能）_
